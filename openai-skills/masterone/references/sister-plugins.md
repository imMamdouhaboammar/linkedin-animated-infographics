## Capability rule

Do not infer a plugin name, purpose, installed state, permissions, tools, or successful invocation from its URL.

A Sister Plugin is an optional capability only when the current host exposes it or the user explicitly opens/invokes it. If it is not observed, continue locally with the strongest available workflow and do not claim that a handoff occurred.

Never auto-install a Sister Plugin, never require it for core infographic production, and never make the current plugin's PASS depend on an unavailable companion.

## Handoff contract

When a Sister Plugin is actually available and materially useful:

1. keep the current evidence boundary authoritative
2. send a bounded job, not the whole project context by default
3. state the requested output and acceptance criteria
4. treat returned material as input requiring normal evidence/design review
5. record what was actually used
6. never describe an unobserved or failed invocation as completed

Useful bounded handoffs may include research, writing refinement, workspace organization, visual critique, or other specialized jobs when the exposed companion capability clearly matches the need.

## No hidden dependency

The public ChatGPT/Codex package remains self-contained. Sister Plugins may improve a workflow when available, but they are not bundled runtime dependencies and their URLs do not prove availability.
